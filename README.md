# Хакатон «Оптимальный маршрут»: решение транспортной задачи

Программа на Python 3.15 находит план перевозок **минимальной стоимости**: читает условие из `in.txt` и записывает ответ в `out.txt`.

- **Метод:** прямо-двойственный (венгерский) метод для транспортной задачи – потенциалы + максимальный поток по «нулевым» клеткам. Готовые решатели задач оптимизации не используются: алгоритм целиком реализован в этом репозитории, из сторонних библиотек нужен только NumPy.
- **Точность:** ответ всегда оптимален. Оптимальность не «на глаз»: программа умеет её доказать (`python main.py --verify`), а отдельная программа `tools/check.py` проверяет готовый `out.txt` независимо от решателя.
- **Скорость:** конкурсный тест 1000×1000 решается примерно за **0,2 с** (вместе с запуском Python, загрузкой NumPy, чтением и записью файлов).

Подробное описание метода, доказательство корректности и ответы на возможные вопросы – в файле [docs/ALGORITHM.md](docs/ALGORITHM.md).

## Задача

Есть N поставщиков с запасами A₁…A_N и M потребителей с потребностями B₁…B_M. Перевозка единицы груза от поставщика i к потребителю j стоит C[i][j]. Нужно найти объёмы перевозок X[i][j] ≥ 0, при которых вывоз от каждого поставщика не превышает его запаса, потребности всех потребителей удовлетворены, а сумма затрат Σ C[i][j]·X[i][j] минимальна.

### Входные данные (`in.txt`)

N+3 строки целых чисел, разделённых пробелами:

- первая строка – N и M;
- вторая строка – запасы поставщиков A₁ … A_N;
- третья строка – потребности потребителей B₁ … B_M;
- следующие N строк – цены перевозок, по M чисел в строке.

### Выходные данные (`out.txt`)

N+1 строка целых чисел:

- первая строка – сумма затрат;
- следующие N строк – объёмы перевозок, по M чисел в строке.

### Пример

`in.txt`:

```
3 4
30 40 20
20 30 30 10
2 3 2 4
3 2 5 1
4 3 2 6
```

`out.txt`:

```
170
20 0 10 0
0 30 0 10
0 0 20 0
```

Проверка: 2·20 + 2·10 + 2·30 + 1·10 + 2·20 = 170.

## Запуск

Положите файл `in.txt` в корень репозитория (там уже лежит пример из задания) и выполните:

```
python main.py
```

Программа создаст `out.txt` и напечатает итог:

```
Поставщиков: 1000, потребителей: 1000
Минимальные затраты: 1415114
Результат записан в out.txt, время работы: 0.180 с
```

Ввода с клавиатуры программа не требует. Время в сообщении отсчитывается от первых строк `main.py` (до загрузки NumPy) до завершения записи `out.txt`.

Вариант с доказательством оптимальности – после записи `out.txt` программа дополнительно проверяет найденный план:

```
python main.py --verify
```

## Проверка ответа

`tools/check.py` читает `in.txt` и `out.txt` и проверяет всё, что требует задание: формат файла, допустимость плана, совпадение суммы в первой строке со стоимостью плана и оптимальность. Решатель при этом не используется – оптимальность проверяется другим алгоритмом (подбор потенциалов методом Беллмана – Форда).

```
python tools/check.py
```

```
Формат верен, план допустим, сумма затрат 1415114 совпадает с планом
План оптимален: дешевле перевезти нельзя
```

Случайные входные данные нужного размера создаёт генератор (запасы, потребности и цены – от 1 до 999, как в конкурсном тесте):

```
python tools/generate.py 1000 1000
python main.py
python tools/check.py
```

Чтобы вернуть маленький пример, скопируйте `examples/in.txt` в корень репозитория.

## Метод решения (кратко)

У каждого поставщика есть потенциал u[i], у каждого потребителя – потенциал v[j]. Алгоритм всегда держит их такими, что «приведённая стоимость» любой клетки r[i][j] = C[i][j] − u[i] − v[j] неотрицательна, а груз возит только по клеткам, где она равна нулю. Как только по таким «нулевым» клеткам удаётся развезти весь груз, план оптимален – это классическое условие оптимальности метода потенциалов.

1. **Начало.** u[i] – минимум строки, v[j] – минимум столбца после вычитания u. В каждой строке и каждом столбце появляется нулевая клетка.
2. **Шаг «поток».** По нулевым клеткам развозится максимум груза (алгоритм Диница: поиск в ширину + поиск в глубину). Уже назначенные перевозки при этом могут перераспределяться.
3. **Шаг «потенциалы».** Если груз остался, потенциалы сдвигаются на минимально возможную величину так, чтобы появились новые нулевые клетки, а все перевозки остались на нулевых клетках. Затем снова шаг 2.

Что делает программу быстрой:

- **Список клеток-кандидатов.** Из миллиона клеток в оптимальный план попадают только самые дешёвые (в конкурсном тесте – с ценой не больше 13 при ценах до 999). Алгоритм работает с 3 % самых дешёвых клеток и сам расширяет список, если его перестаёт хватать. Это не эвристика: в коде проверяется условие, при котором пропущенные клетки гарантированно не влияют на ответ.
- **NumPy** выполняет все операции над миллионом клеток и над списком кандидатов; на чистом Python остаются только обходы маленькой сети нулевых клеток (около 2000 дуг).
- **Мало шагов.** Потенциалы в конкурсном тесте сдвигаются всего 19 раз.
- **Быстрый ввод-вывод.** Миллион чисел читается одним вызовом NumPy (~20 мс); строки ответа, состоящие почти из одних нулей, собираются из готовых кусков (~4 мс).

## Время работы

Полное время `python main.py` (от запуска интерпретатора до завершения), лучший из 5 запусков. Замеры – на сервере Intel Xeon 2,1 ГГц (Linux, Python 3.15, NumPy 2.5.4); на целевой платформе хакатона цифры будут другими, но того же порядка. Данные – `tools/generate.py` (числа от 1 до 999); каждый ответ проверен `tools/check.py`.

| Размер задачи | Время |
|---|---|
| 100 × 100 | 0,10 с |
| 500 × 500 | 0,13 с |
| **1000 × 1000 (конкурсный тест)** | **0,18 с** |
| 2000 × 2000 | 0,37 с |
| 200 × 3000 | 0,17 с |

Из 0,18 с на конкурсном тесте около 0,10 с – запуск Python и загрузка NumPy, 0,02 с – чтение `in.txt`, 0,06 с – само решение, меньше 0,01 с – запись `out.txt`.

Для сравнения, другие методы, реализованные и измеренные при разработке на том же тесте (только время решения, без ввода-вывода): метод потенциалов с деревом базиса – 1,2–1,9 с; венгерский метод с отдельным поиском пути для каждого поставщика – 2,3 с. Все три метода дали одинаковую стоимость 1 415 114.

## Структура репозитория

```
├── main.py              – точка входа: читает in.txt, решает, пишет out.txt
├── solver.py            – алгоритм: потенциалы, поток по нулевым клеткам, проверка оптимальности
├── transport_io.py      – чтение in.txt и запись out.txt
├── in.txt               – входные данные (пример из задания)
├── requirements.txt     – сторонние библиотеки (NumPy)
├── examples/            – пример входного и выходного файлов из задания
├── tools/generate.py    – генератор случайных входных данных
├── tools/check.py       – независимая проверка out.txt
├── tests/               – автоматические тесты
├── docs/ALGORITHM.md    – подробное описание метода
└── README.md            – это описание
```

## Тесты

```
python -m unittest discover tests
```

Тесты сверяют ответы с независимым эталонным решателем (`tests/reference.py`, простой алгоритм потока минимальной стоимости) на сотнях случайных задач, проверяют крайние случаи (нулевые запасы, одинаковые цены, отрицательные и очень большие числа, прямоугольные таблицы, открытую задачу) и форматы файлов (окончания строк Windows и Unix, метка BOM).
