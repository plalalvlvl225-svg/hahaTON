# Как найти и проверить самый дешёвый план перевозок

## Что означает ответ 1 415 114

В конкурсном файле 1000 поставщиков, 1000 потребителей и миллион тарифов от 1 до 999. Перевезти нужно 507 067 единиц товара. Выходной файл содержит объём для каждого из миллиона маршрутов. В полученном плане заняты 2054 маршрута. Цена их перевозок по исходным тарифам — **1 415 114**. Для всех допустимых планов независимо вычислена нижняя граница **1 415 114**. Совпадение этих величин доказывает глобальный минимум.

Время и стоимость отвечают на разные вопросы. Стоимость доказывается математически для данного входа. Для скорости приводятся измерения на конкретной машине, полная процедура и свойства входных данных.

## Как выбирался метод

Сначала имеет смысл построить любой допустимый план. Метод северо-западного угла работает так. Берём первую незакрытую строку и первый незакрытый столбец, отгружаем минимум из остатка запаса и остатка спроса. Когда запас исчерпан, переходим к следующей строке, когда спрос удовлетворён — к следующему столбцу. На конкурсном файле его стоимость составила 255 516 368. Этот результат показывает, сколько стоит игнорировать тарифы.

Следующая идея — проходить маршруты в порядке роста тарифа и в каждом отправлять всё, что возможно в данный момент. При разрешении равных тарифов в порядке строк на том же входе получается 3 602 603. Иногда потребитель с двумя дешёвыми поставщиками получает товар от того, кто был единственным дешёвым вариантом для другого потребителя. Тогда приходится пересмотреть уже назначенную перевозку. Даже при очень дешёвом старте жадный выбор не даёт способа установить, что результат окончательный.

Отсюда два требования к основному алгоритму. Он должен уметь перераспределять уже отправленный груз и распознавать достижение глобального минимума. Оба реализованных метода используют **приведённую стоимость**. При повторяющихся тарифах множество маршрутов часто одновременно получают нулевую приведённую стоимость. На них можно быстро построить целый поток. При широком разбросе тарифов новые маршруты могут появляться по одному. Тогда выгодно улучшать уже допустимый план переносами по циклам. Эти два режима проверялись на отдельных прототипах и на полных файловых запусках.

## Математическая модель и сертификат

Пусть Aᵢ — запас поставщика i, Bⱼ — спрос потребителя j, Cᵢⱼ — цена доставки единицы, Xᵢⱼ — выбранный объём. Баланс исходных данных гарантирует равенство суммарного запаса и спроса. Если полностью закрыт спрос и ни один поставщик не превысил свой запас, то каждый поставщик вывез ровно весь запас. Поэтому ограничения и цель можно записать так.

```text
Xᵢⱼ ≥ 0
Σⱼ Xᵢⱼ = Aᵢ                         для каждого i
Σᵢ Xᵢⱼ = Bⱼ                         для каждого j
Z = Σᵢⱼ Cᵢⱼ Xᵢⱼ                     минимизируем
```

Подберём каждому поставщику число uᵢ и каждому потребителю число vⱼ. Эти числа называют потенциалами. Если на каждом маршруте uᵢ + vⱼ ≤ Cᵢⱼ, то для любого допустимого плана выполняется

```text
Σᵢⱼ Cᵢⱼ Xᵢⱼ  ≥  Σᵢⱼ (uᵢ + vⱼ) Xᵢⱼ
               =  Σᵢ uᵢ Aᵢ + Σⱼ vⱼ Bⱼ.
```

Первый переход использует неотрицательность объёмов. Второй просто собирает слагаемые одного поставщика и одного потребителя. Справа стоит число, которое зависит от входных данных и потенциалов и служит нижней границей стоимости **любого** плана.

Разность rᵢⱼ = Cᵢⱼ − uᵢ − vⱼ называют приведённой стоимостью. Если все rᵢⱼ ≥ 0, а на каждой положительной перевозке rᵢⱼ = 0, то в формуле выше достигается равенство. Более дешёвого плана существовать не может. Условия можно проверить точно, обычной целочисленной арифметикой.

### Как доказать ответ 170 из условия на бумаге

Для таблицы 3 × 4 подходят u = (2, 1, 2) и v = (0, 1, 0, 0). Эти числа получаются из минимумов строк и оставшихся минимумов столбцов. Например, для A₂ → B₂ сумма потенциалов равна 1 + 1 = 2, ровно тарифу. Для A₂ → B₃ она равна 1 + 0 = 1 при тарифе 5. Аналогично проверяются остальные десять клеток. Нижняя граница равна 30×2 + 40×1 + 20×2 + 30×1 = 170. План в README обходится в 20×2 + 10×2 + 30×2 + 10×1 + 20×2 = 170. Это короткое доказательство можно показать комиссии без запуска программы.

## Что происходит с входными данными

`main.py` читает N и M, запасы и потребности, проверяет баланс и длину каждой строки. Строки матрицы обрабатываются по одной. Обычные тарифы NumPy считывает прямо в целочисленный массив. Если в строке есть последовательность из 19 и более цифр, тарифы этой строки сначала разбираются как целые Python. Так определяется необходимость расширить тип до того, как ограниченный машинный тип мог бы потерять значение. Поддерживаются пробелы, окончания строк Windows и UTF-8 BOM в начале файла.

Поставщик с нулевым запасом и потребитель с нулевым спросом заранее получают нулевые перевозки. В `transport.solve` соответствующие строки и столбцы удаляются из вычислений, затем номера восстанавливаются для вывода. Если активен ровно один поставщик или один потребитель, план однозначно задаётся балансами. При нулевом суммарном объёме программа сразу получает пустые строки разреженного плана.

Из каждой строки стоимости можно вычесть её минимум sᵢ. Любой допустимый план подешевеет ровно на Σᵢ sᵢAᵢ, потому что объём строки фиксирован. Вычитание минимумов столбцов имеет такое же свойство. После этих операций таблица W неотрицательна, в каждой активной строке и каждом активном столбце есть хотя бы один ноль. Оптимальные планы исходной и преобразованной задач совпадают. Финальная стоимость всегда подсчитывается по исходной таблице C.

## Основной путь на конкурсных данных

Функция `solve_tight` начинает с нулевых потенциалов на нормализованной таблице W и пустого плана. Это допустимые потенциалы, поскольку W ≥ 0. Программа последовательно поддерживает два свойства. Для всех маршрутов rᵢⱼ = Wᵢⱼ − uᵢ − vⱼ ≥ 0. Каждый уже перевезённый объём лежит на маршруте с rᵢⱼ = 0. Таким образом, когда удастся закрыть весь спрос, доказательство оптимальности будет готово одновременно с планом.

**Как увеличить объём.** От поставщика с остатком груза разрешён прямой шаг к любому потребителю с rᵢⱼ = 0. Если спрос этого потребителя ещё не закрыт, туда можно направить товар. Если он уже получает груз, допустим обратный шаг к одному из его действующих поставщиков. Он означает отмену части прежней перевозки. От этого поставщика можно искать следующий прямой шаг. Поиск в ширину запоминает предшественников, пока не доберётся до незакрытого потребителя.

По найденному пути отправляется максимум, который позволяет самое узкое место. Это минимум из свободного запаса в начале пути, незакрытого спроса в конце и объёмов всех отменяемых перевозок. На прямых шагах объём прибавляется, на обратных вычитается. Каждый промежуточный участник одновременно получает и отдаёт один и тот же объём, поэтому его суммарный баланс сохраняется. Все количества остаются целыми.

**Зачем менять потенциалы.** Иногда остаётся свободный запас, но пути к незакрытому спросу по текущим нулевым маршрутам уже нет. Обозначим R множество достижимых поставщиков, S — достижимых потребителей. Все свободные корни рассматриваются. Если поиск из одного корня закрыл область, последующие успешные пути в этой фазе её не затронут. Код сохраняет такие области, чтобы не обходить их повторно.

В каждой клетке из R в столбец вне S приведённая стоимость положительна. Иначе этот потребитель был бы достижим. Выбирается минимальное из этих значений Δ. Для строк из R добавляем Δ к uᵢ, для столбцов из S вычитаем Δ из vⱼ. Внутри R × S поправки сокращаются. Из R наружу каждая оценка уменьшается максимум до нуля. Снаружи в S оценки увеличиваются. Остальные оценки сохраняют значение. Положительная перевозка не может пересекать границу в направлении с изменившейся оценкой, поскольку её прямой и обратный шаги были доступны. Так сохраняются оба свойства метода и появляется хотя бы один доступный переход через прежнюю границу.

**Как представлено множество соседей.** В каждой строке NumPy вычисляет маску rᵢⱼ = 0, а `packbits` упаковывает восемь признаков в байт. Затем строка становится одним целым Python, где бит j соответствует потребителю j. Пересечение с маской незакрытого спроса сразу отвечает, есть ли прямая доставка. Массив из миллиона объектов-рёбер для этого не нужен. Обратные шаги хранятся только для фактически положительных перевозок. Такой способ одинаково применим к таблице с несколькими выгодными маршрутами на строку и к таблице с тысячей одинаковых тарифов.

## Пример, в котором приходится отменять перевозку

Пусть каждый из трёх поставщиков имеет одну единицу товара, каждому из трёх потребителей нужна одна единица. Возьмём такую матрицу.

| Поставщик | B₁ | B₂ | B₃ |
|---|---:|---:|---:|
| A₁ | 0 | 2 | 3 |
| A₂ | 0 | 5 | 7 |
| A₃ | 4 | 0 | 0 |

1. В начале все потенциалы нулевые. По нулевым тарифам программа отправляет единицу A₁ → B₁ и единицу A₃ → B₂. У A₂ остался товар, у B₃ остался спрос.
2. Из A₂ можно дойти до B₁, а оттуда вернуть прежнюю перевозку поставщику A₁. Поэтому R = {A₁, A₂}, S = {B₁}. Четыре тарифа из R к B₂ и B₃ равны 2, 3, 5 и 7. Поправка Δ равна 2.
3. Новые потенциалы u = (2, 2, 0), v = (−2, 0, 0). Маршрут A₁ → B₂ получает нулевую оценку, поскольку 2 − 2 − 0 = 0. Исходная цена этой доставки по-прежнему равна двум.
4. Открывается путь A₂ → B₁ → A₁ → B₂ → A₃ → B₃. Отменяются A₁ → B₁ и A₃ → B₂. В результате A₂ везёт в B₁, A₁ — в B₂, A₃ — в B₃.
5. План стоит 0 + 2 + 0 = 2. Двойственная нижняя граница равна (2 + 2 + 0) + (−2 + 0 + 0) = 2. Проверены как допустимость, так и оптимальность.

## Когда срабатывает второй алгоритм

Быстрому методу отведены 32 фазы. На официальной таблице хватает 20. Если за 32 фазы полный план не построен, частичные перевозки отбрасываются и программа решает задачу транспортным симплексом с собственного допустимого начального плана. Когда даже после нормализации для тарифов нужна произвольная точность, сразу используется симплекс. Лимит фаз ограничивает время, потраченное на первую попытку. Он не является условием приёмки приближённого ответа.

## Как транспортный симплекс улучшает допустимый план

### План и базис

Представим поставщиков и потребителей вершинами графа. Клетка таблицы соединяет своего поставщика со своим потребителем. Базис состоит из маршрутов, которые образуют дерево на всех активных вершинах. У дерева из `n + m` вершин ровно `n + m − 1` рёбер. Достаточно знать объёмы на этих рёбрах. У вершины-листа только один маршрут, и его объём определяется оставшимся запасом или спросом. Если убрать этот лист и вычесть его поставку у соседа, то же рассуждение применимо к следующему листу.

`_initial_basis` берёт дешёвые клетки из списка кандидатов и отправляет по каждой доступной клетке меньшую из двух величин — остаток запаса и остаток спроса. Незакрытые остатки соединяет по порядку. При каждой положительной отправке заканчивается хотя бы один из двух остатков. Так образуется лес. Например, когда два поставщика с запасом по 5 полностью обслужили двух разных потребителей со спросом по 5, получились две отдельные пары. Для базиса на четырёх вершинах нужен третий маршрут. Код соединяет пары ребром с объёмом 0. Нулевое ребро помогает однозначно определить путь между любыми вершинами и вычислить потенциалы. В словари итогового плана попадают только положительные отправки. При записи файла программа подставит в остальные клетки нули.

### Цена изменения на одну единицу

Нумерация в коде начинается с нуля. Маршруту из строки `i` в столбец `j` соответствует номер `i * m + j`. У вершин своя нумерация. Поставщик имеет номер `i`, потребитель — `n + j`. В `_Basis` первый поставщик получает потенциал 0. Потенциалы остальных вершин определяются при обходе дерева из равенств

```text
p[поставщик] − p[потребитель] = w[i,j]
```

Здесь `w` — нормализованные тарифы. Для любой клетки можно вычислить её приведённую стоимость `r = w[i,j] − p[i] + p[n+j]`. На базисных рёбрах она равна нулю. Если у нового маршрута `r < 0`, его добавление замыкает единственный цикл. Вдоль цикла чередуем прибавление и вычитание одного количества `θ`, начиная с прибавления на новом маршруте. В каждой затронутой строке и каждом столбце встречаются один плюс и один минус. Все суммы сохраняются. Слагаемые с потенциалами также сокращаются, поэтому изменение общей стоимости равно `θ × r`.

### Один обмен на четырёх клетках

Разберём шаг функции `solve_simplex`. У поставщиков запасы 7 и 5, у потребителей спрос 6 и 6. Исходные тарифы — 2, 3 в первой строке и 4, 12 во второй. После вычитания минимумов строк (2 и 4), затем минимумов столбцов (0 и 1) получаем тарифы 0, 0 и 0, 7. Для любого допустимого плана разница между исходной и нормализованной стоимостью равна `2×7 + 4×5 + 1×6 = 40`.

| Маршрут | Номер | Исходный тариф | Начальный объём | Обмен | Новый объём |
|---|---:|---:|---:|---:|---:|
| A₁ → B₁ | 0 | 2 | 6 | −5 | 1 |
| A₁ → B₂ | 1 | 3 | 1 | +5 | 6 |
| A₂ → B₁ | 2 | 4 | 0 | +5 | 5 |
| A₂ → B₂ | 3 | 12 | 5 | −5 | 0 |

В начальном дереве три занятых маршрута с номерами 0, 1 и 3. По ним получаем потенциалы поставщиков `(0, 7)` и потребителей `(0, 0)`. Для свободного маршрута № 2 приведённая стоимость равна `0 − 7 + 0 = −7`. Чтобы добавить единицу на A₂ → B₁, убираем единицу с A₁ → B₁, добавляем на A₁ → B₂ и убираем с A₂ → B₂. На маршрутах со знаком минус лежат 6 и 5 единиц. Следовательно, максимальный безопасный перенос равен 5. Маршрут № 3 опустел и выходит из дерева. Исходная стоимость упала с `6×2 + 1×3 + 5×12 = 75` до `1×2 + 6×3 + 5×4 = 40`. Разница составляет ровно `5×7 = 35`. Нормализованная стоимость стала нулевой, а все нормализованные тарифы неотрицательны. В этом примере нижняя граница достигнута уже после одного обмена.

### Выбор нового ребра и остановка

В начале `_shortlist` объединяет до 24 дешёвых маршрутов каждой строки и до 24 каждого столбца. Функция `_optimize_candidates` просматривает список блоками по 2048 клеток. В первом блоке с отрицательной приведённой стоимостью выбирает клетку с наименьшим значением. Код `pivot` поднимается от обоих концов нового ребра по родителям до их общего предка и находит цикл. Разрыв одного старого ребра делит дерево на две части. Для восстановления равенства потенциалов на новом ребре достаточно сдвинуть все потенциалы в одной части на одну и ту же величину. Именно эту часть обходит `_reattach`.

Если в позиции со знаком минус стоит базисный ноль, перенос `θ` равен нулю. Базис меняется, стоимость пока остаётся той же. Чтобы исключить повторение таких обменов по кругу, после восьми последовательных переносов нулевого объёма код применяет правило Бланда. Выбирается наименьший номер среди всех допустимых входящих рёбер текущего списка. При равенстве минимальных объёмов всегда выходит ребро с наименьшим номером. Программа сохраняет этот порядок до первого строгого уменьшения стоимости.

Когда кандидаты исчерпаны, `solve_simplex` проверяет **все** клетки. Каждая пропущенная клетка с отрицательной приведённой стоимостью попадает в список, и улучшение продолжается. Если во всей матрице `r ≥ 0`, то `w[i,j] ≥ p[i] − p[n+j]`. Умножив это неравенство на объёмы любого допустимого плана и просуммировав, получим общую нижнюю границу `Σ запас[i]×p[i] − Σ спрос[j]×p[n+j]`. У найденного плана все положительные отправки идут по базисным рёбрам, где действует равенство. Следовательно, стоимость плана совпадает с нижней границей. Это доказывает глобальный минимум.

## Большие числа и полный файловый вывод

**Объёмы.** Все запасы, потребности, промежуточные объёмы и итоговая стоимость хранятся как целые Python. При переносе по пути или по циклу программа за одно действие переносит весь допустимый объём. Если умножить все запасы и потребности на 10⁶⁰, при тех же тарифах, порядке обхода и выборе равных вариантов объёмы каждого переноса умножатся на 10⁶⁰. Операции с более длинными числами и их запись отнимают больше времени, но дополнительный цикл на каждую единицу товара не появляется.

**Тарифы и потенциалы.** Для типичных цен выгодны плотные массивы NumPy с `int32` или `int64`. При выборе типа учитывается размер промежуточных значений. Потенциал вершины дерева — знаковая сумма тарифов вдоль пути длиной меньше n + m. В оценке участвуют две такие величины и один тариф. На быстром пути каждая из 32 поправок также ограничена максимальным нормализованным тарифом Wmax. Действительно, у любого ещё незакрытого потребителя потенциал v остаётся нулевым. Из любой строки с остатком груза тариф к нему не превосходит Wmax, а потенциал строки u неотрицателен. Поэтому минимум оценки на разрезе не больше Wmax. Код сравнивает консервативную оценку (2(n + m) + 128) × Wmax с диапазоном выбранного типа. Если запаса разрядности недостаточно, используются целые Python.

**Очень крупная единица цены.** Рассмотрим тарифы вида Cᵢⱼ = D·Tᵢⱼ + sᵢ + tⱼ, где D, например, равен 10⁵⁰. Часть sᵢ + tⱼ даёт одинаковую суммарную надбавку любому допустимому плану. В разности четырёх клеток Hᵢⱼ = Cᵢⱼ − Cᵢ₀ − C₀ⱼ + C₀₀ эти надбавки полностью сокращаются. Наибольший общий делитель всех H определяет масштаб, на который таблицу можно разделить без округления. Если на небольшой выборке НОД уже равен единице, вычислять его на остальных клетках бессмысленно. Деление разрешается только после проверки всей таблицы. Если все H нулевые, исходная цена целиком состоит из строковых и столбцовых надбавок, и все допустимые планы имеют одну стоимость.

После точного деления `_compress_wide_costs` добавляет в столбец j целую часть C₀ⱼ / D. Эта добавка одинакова для всей колонки и сохраняет оптимальность. Она помогает получить начальные потенциалы, для которых быстрый метод хорошо работает и после пересчёта денежных единиц. Стоимость файла результата по-прежнему вычисляется по подлинным тарифам.

**Вывод.** Внутри решателя каждой строке плана соответствует словарь «номер потребителя → положительный объём». Для подсчёта цены достаточно пройти по этим словарям. `write_plan` приводит тариф к целому Python до умножения, складывает произведения и записывает сумму. Затем создаёт одну строку из M нулей, подставляет положительные отправки и записывает её. Поэтому даже при разреженном внутреннем представлении файл всегда содержит полную матрицу N × M.

## Как проверить чужой план без повторного решения задачи

У программы `tools/check_plan.py` на входе только `in.txt` и `out.txt`. Она проверяет число строк и столбцов, неотрицательность поставок, суммы по каждой строке и столбцу, а также стоимость по исходным тарифам. Даже полностью допустимый план с правильной первой строкой может оказаться дорогим. Для проверки оптимальности нужны потенциалы.

На каждом маршруте с положительной поставкой должно выполняться равенство потенциалов и тарифа. Проверяющая программа хранит потенциалы двух долей в одной системе знаков. Для маршрута i → j она требует pⱼ − pᵢ = Cᵢⱼ. Обход положительных рёбер задаёт значения p с точностью до одной общей добавки для каждой компоненты связности. Противоречие на цикле сразу обнаруживается. Оставшиеся ограничения pⱼ − pᵢ ≤ Cᵢⱼ задают верхние границы разностей между добавками компонент. Проверяющая программа решает эту систему алгоритмом Беллмана — Форда. Отрицательный цикл означает, что подобрать допустимые потенциалы невозможно.

В конце проверяются неравенства **на всех исходных маршрутах**, а нижняя граница вычисляется независимо от заявленной цены. Для конкурсного результата проверяющая программа печатает

```text
1000 x 1000, положительных маршрутов 2054, компонент связности 1
Стоимость плана = 1415114, двойственная нижняя граница = 1415114
```

2054 положительных перевозки при 2000 вершинах допустимы. Ограничение n + m − 1 относится к числу рёбер древесного базиса симплекса. Метод увеличивающих путей может выбрать другой оптимальный план. Для оценки достаточно допустимости и минимальной стоимости.

## Сложность и границы производительности

При N × M входных тарифов и стольких же обязательных полях вывода любой алгоритм должен хотя бы один раз прочитать и записать эту таблицу. Нижняя граница по числу полей составляет Ω(NM). При длинных числах важен и полный объём текста в байтах.

Быстрый метод за фазу вычисляет оценки и маски за O(nm) операций с элементами массива. Сверх этого он ищет увеличивающие пути в остаточной сети. Их число и длина зависят от структуры тарифов и балансов. Достижимость хранится битовыми масками, а обратные маршруты — по фактическим положительным перевозкам. Память для основных матриц и плана ограничена O(NM) ячеек. В режиме произвольной точности размер одной ячейки зависит от числа цифр.

У симплекса в дереве n + m − 1 рёбер. Обход цикла и обновление затронутой части дерева занимают O(n + m) в худшем случае одного обмена. Поиск следующего ребра может потребовать просмотра всего текущего списка кандидатов. После его оптимизации нужен проход по всей матрице. Число обменов зависит от задачи. Эти оценки объясняют измерения, но не задают одинакового предела времени для всех матриц 1000 × 1000.

## Какие проверки выполнены

В репозитории есть тесты с полным перебором всех допустимых целочисленных планов на маленьких матрицах. В них проверяются обычный решатель, принудительный симплекс, необходимость отменить уже выбранный маршрут, нулевые балансы, равные и отрицательные тарифы, переход за границы `int64`, длинная общая единица цены, файловый ввод и вывод 5000-значного числа. Отдельный тест даёт проверяющей программе допустимый субоптимальный план с правильной суммой и требует его отклонить.

При разработке выполнены дополнительные независимые проверки. На 1776 небольших задачах и основной решатель, и принудительно включённый симплекс дали тот же результат, что исчерпывающий перебор. Для 3848 состояний поиска потока проверялись объём, минимальный разрез и достижимые вершины остаточной сети. Проверялись также вырожденные повороты симплекса, случаи, когда пришлось добавить пропущенный маршрут, и матрицы с тысячами цифр в коэффициентах. Эти испытания дополняют математическую проверку конкретного конкурсного файла.

Миллион новых тарифов можно получить из настоящего конкурса так. Умножить каждую цену на 10⁵⁰ и прибавить i − j, а все запасы и потребности умножить на 10⁶⁰. Тогда заранее известно, каким должен быть оптимум преобразованной задачи.

```text
Z' = 10⁶⁰ × (10⁵⁰ × 1 415 114 + Σᵢ i Aᵢ − Σⱼ j Bⱼ)
```

Программа выдала именно это целое число. Оно также совпало с нижней границей, восстановленной по фактическому выходному файлу.
