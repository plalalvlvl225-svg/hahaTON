# Алгоритм на пальцах

Объяснение без формул, с подсчётом руками. Полное описание с доказательствами – в [ALGORITHM.md](ALGORITHM.md).

## 1. Задача

Есть склады и магазины. В таблице – цена перевозки одной единицы товара со склада в магазин. Нужно развезти весь товар и заплатить как можно меньше.

Пример из задания:

```
          B1   B2   B3   B4   есть на складе
A1         2    3    2    4        30
A2         3    2    5    1        40
A3         4    3    2    6        20
нужно     20   30   30   10
```

## 2. Главный фокус: из строки можно вычесть одно и то же число

Склад A1 в **любом** плане отправит ровно 30 единиц – весь свой товар. Неважно, куда.

Вычтем из всех цен строки A1 по 2. Тогда **любой** план подешевеет ровно на 30 · 2 = 60. Все планы подешевели одинаково. Значит, какой план был самым дешёвым, такой им и остался.

То же самое со столбцом: магазин B2 в любом плане получит ровно 30 единиц. Если вычесть из столбца B2 по 1, любой план подешевеет на 30 · 1 = 30.

**Вывод:** из строк и столбцов можно вычитать (и прибавлять) числа, и лучший план от этого не меняется. Нужно только запомнить, сколько всего вычли, чтобы потом вернуть.

## 3. Вычитаем, пока не появятся нули

**Из каждой строки вычитаем её минимум.** Минимумы строк: A1 – 2, A2 – 1, A3 – 2.

```
          B1   B2   B3   B4
A1         0    1    0    2      (вычли 2)
A2         2    1    4    0      (вычли 1)
A3         2    1    0    4      (вычли 2)
```

**Из каждого столбца вычитаем его минимум.** Минимумы столбцов: B1 – 0, B2 – 1, B3 – 0, B4 – 0.

```
          B1   B2   B3   B4
A1         0    0    0    2
A2         2    0    4    0
A3         2    0    0    4
вычли      0    1    0    0
```

Это новая таблица цен. В ней нет отрицательных чисел, а **нули** – это маршруты, которые в новой таблице **бесплатные**.

**Честный маршрут – это просто клетка с нулём в новой таблице.**

## 4. Возим только по нулям

Если удастся развезти весь товар только по нулевым клеткам, то в новой таблице план стоит **0**. Дешевле нуля быть не может (отрицательных цен в таблице нет). Значит, этот план – самый дешёвый. А раз лучший план от вычитаний не меняется (пункт 2), он самый дешёвый и в исходной таблице.

Развозим по нулям:

- B1 может получить товар только от A1 (единственный ноль в столбце): **A1 → B1: 20**.
- B4 – только от A2: **A2 → B4: 10**.
- У A2 осталось 30, его второй ноль – B2: **A2 → B2: 30**. B2 заполнен.
- A3 (20 единиц) везёт в B3: **A3 → B3: 20**.
- У A1 осталось 10, везёт в B3: **A1 → B3: 10**. B3 заполнен.

Всё развезено, только по нулям.

## 5. Сколько это стоит по-настоящему

В новой таблице план стоит 0. Чтобы получить настоящую цену, возвращаем всё, что вычли:

```
строки:   A1: 30 единиц · 2 = 60
          A2: 40 единиц · 1 = 40
          A3: 20 единиц · 2 = 40
столбцы:  B2: 30 единиц · 1 = 30
итого                       = 170
```

Проверка по исходной таблице: 2·20 + 2·10 + 2·30 + 1·10 + 2·20 = **170**. Совпало – и это минимум.

## 6. Что такое потенциал

**Потенциал – это сколько всего вычли из строки или столбца.**

- Потенциалы складов: A1 = 2, A2 = 1, A3 = 2.
- Потенциалы магазинов: B1 = 0, B2 = 1, B3 = 0, B4 = 0.

Цена клетки в новой таблице = исходная цена − потенциал строки − потенциал столбца. Например, A1 → B2: 3 − 2 − 1 = 0, ноль, значит, маршрут честный. A1 → B4: 4 − 2 − 0 = 2, не ноль, значит, нечестный.

Никакой магии: потенциалы – это просто записанные вычитания.

## 7. Что делать, если по нулям всё не развезти

Пример поменьше:

```
          B1   B2   есть
A1         1    5     5
A2         2    9     5
нужно      3    7
```

Минимумы строк – 1 и 2, потом минимумы столбцов – 0 и 4:

```
          B1   B2
A1         0    0      (вычли 1)
A2         0    3      (вычли 2)
вычли      0    4
```

Развозим по нулям: B2 может получить товар только от A1 – **A1 → B2: 5**. B1 получает от A2 – **A2 → B1: 3**.

Затор: у A2 осталось 2 единицы, а B2 недополучил 2. У A2 единственный ноль – B1, а он уже полон. Перестановки тоже не помогут: A1 мог бы освободить место, но B1 занят.

**Выход – сделать новый ноль.** Застряли A2 и его заполненный магазин B1. Самая дешёвая клетка, ведущая от застрявших наружу, – A2 → B2 = 3.

- Вычитаем 3 из строки A2: получается `−3  0`.
- Чтобы не было минуса, прибавляем 3 к столбцу B1 (пункт 2: прибавлять тоже можно).

```
          B1   B2
A1         3    0
A2         0    0      ← A2 → B2 стал нулём!
```

Клетка A1 → B1 стала 3, но по ней ничего не возили, так что это не мешает.

Почему именно 3: это наименьшее число, которое даёт новый ноль. Вычтем меньше – нуля не будет, вычтем больше – получится отрицательное число.

Теперь **A2 → B2: 2**. Всё развезено по нулям.

Настоящая цена – возвращаем вычтенное:

```
A1: 5 · 1 = 5      A2: 5 · (2 + 3) = 25
B1: 3 · (0 − 3) = −9      B2: 7 · 4 = 28
итого: 5 + 25 − 9 + 28 = 49
```

Проверка: 5·5 + 3·2 + 2·9 = **49**.

Потенциалы здесь: A1 = 1, A2 = 5, B1 = −3, B2 = 4. Отрицательный потенциал означает, что к столбцу в итоге больше прибавили, чем вычли.

## 8. Весь алгоритм

1. Вычесть минимумы строк, потом минимумы столбцов. Появятся нули.
2. Развезти по нулям всё, что можно (при необходимости переставляя уже назначенные перевозки).
3. Если товар остался – вычесть из «застрявших» строк и прибавить к их столбцам наименьшее число, которое создаёт новый ноль.
4. Повторять 2–3, пока всё не развезено.

Наша программа делает ровно это. На конкурсном тесте 1000×1000 шаг 3 понадобился всего 19 раз.

## 9. Почему программа быстрая

- **Смотрит только на дешёвые клетки.** Нули появляются только там, где исходная цена мала. Поэтому программа держит в памяти лишь 3 % самых дешёвых клеток и следит, чтобы дорогие не могли стать нулём. Если могут – добавляет их. Ответ всегда точный.
- **Делает мало больших шагов.** Вычитание из многих строк сразу выполняет NumPy – быстрая библиотека на C. Классический метод потенциалов делает тысячи мелких шагов на Python (1,2–1,9 с), а наш – 19 больших (0,06 с).
- **Быстро читает и пишет файлы.** Миллион чисел читается одной командой NumPy.

Итог: около 0,2 с на конкурсный тест вместе с запуском Python.
