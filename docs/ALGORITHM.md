# Как устроено решение

Этот документ объясняет метод «с нуля»: что такое потенциалы, почему найденный план оптимален, как работает каждый шаг программы и почему выбран именно этот метод. В конце – ответы на вопросы, которые естественно задать на защите.

Обозначения: N поставщиков (строки таблицы), M потребителей (столбцы), a[i] – запасы, b[j] – потребности, c[i][j] – цены, x[i][j] – объёмы перевозок.

## 1. Главная идея: потенциалы

Припишем каждому поставщику число u[i], каждому потребителю – число v[j]. Это **потенциалы**. Назовём **приведённой стоимостью** клетки число

```
r[i][j] = c[i][j] − u[i] − v[j].
```

**Утверждение 1 (нижняя оценка).** Если r[i][j] ≥ 0 во всех клетках, то стоимость *любого* допустимого плана не меньше числа

```
D = Σ a[i]·u[i] + Σ b[j]·v[j].
```

*Почему.* Распишем стоимость плана, подставив c = r + u + v:

```
Σ c[i][j]·x[i][j] = Σ r[i][j]·x[i][j] + Σ u[i]·(Σj x[i][j]) + Σ v[j]·(Σi x[i][j])
                  = Σ r[i][j]·x[i][j] + Σ u[i]·a[i] + Σ v[j]·b[j].
```

Во второй строке использовано, что в закрытой задаче от поставщика i вывозится ровно a[i], а потребитель j получает ровно b[j]. Первое слагаемое неотрицательно (r ≥ 0, x ≥ 0), значит, стоимость ≥ D.

**Утверждение 2 (условие оптимальности).** Если план возит груз только по клеткам с r[i][j] = 0, то первое слагаемое равно нулю, стоимость плана равна D – а дешевле D не бывает. Значит, план оптимален.

Это ровно то условие, которым заканчивается школьный «метод потенциалов»: для занятых клеток u[i] + v[j] = c[i][j], для свободных u[i] + v[j] ≤ c[i][j]. Разница между методами – в том, как к этому условию прийти:

- метод потенциалов держит *допустимый план* и постепенно исправляет потенциалы (пока есть клетки с r < 0, план улучшается по циклу пересчёта);
- наш метод держит *правильные потенциалы* (всегда r ≥ 0) и постепенно достраивает план, разрешая возить только по клеткам с r = 0.

Клетки с r = 0 будем называть **нулевыми**. Наш метод называется прямо-двойственным (в русскоязычных учебниках – венгерский метод для транспортной задачи).

## 2. Алгоритм целиком

```
1. Начальные потенциалы: u[i] = минимум строки i;
                          v[j] = минимум столбца j в таблице c[i][j] − u[i].
2. Пока не весь груз развезён:
   2.1. ПОТОК: развезти по нулевым клеткам как можно больше груза.
   2.2. Если груз остался – ПОТЕНЦИАЛЫ: сдвинуть u и v так, чтобы
        появились новые нулевые клетки.
3. Записать план. Он оптимален по утверждению 2.
```

После шага 1 все r ≥ 0, в каждой строке и каждом столбце есть нулевая клетка. Дальше свойство «r ≥ 0 везде, перевозки только по нулевым клеткам» сохраняется на каждом шаге – это главный инвариант алгоритма.

### Пример из задания

```
         B1  B2  B3  B4   запас
   A1     2   3   2   4     30
   A2     3   2   5   1     40
   A3     4   3   2   6     20
   спрос 20  30  30  10
```

Минимумы строк: u = (2, 1, 2). После вычитания: строки (0 1 0 2), (2 1 4 0), (2 1 0 4). Минимумы столбцов: v = (0, 1, 0, 0). Приведённые стоимости:

```
   0  0  0  2
   2  0  4  0
   2  0  0  4
```

Шаг «поток» развозит по нулевым клеткам весь груз: A1 → B1: 20, A1 → B3: 10, A2 → B2: 30, A2 → B4: 10, A3 → B3: 20. Груз кончился, сдвигать потенциалы не пришлось. Стоимость 170, нижняя оценка D = 30·2 + 40·1 + 20·2 + 30·1 = 170 – совпали, план оптимален.

### Пример, где нужен сдвиг потенциалов

```
         B1  B2   запас
   A1     1   5     5
   A2     2   9     5
   спрос  3   7
```

Начало: u = (1, 2), v = (0, 4), приведённые стоимости (0 0), (0 3).

Поток: A1 везёт 5 в B2, A2 везёт 3 в B1. У A2 осталось 2 единицы, B2 недополучил 2, но единственная нулевая клетка A2 – это B1, а он заполнен. По нулевым клеткам больше ничего не провезти.

Потенциалы: множество S = {A2, B1} (см. раздел 4), delta = 3 – приведённая стоимость клетки (A2, B2). Увеличиваем u[A2] на 3, уменьшаем v[B1] на 3: u = (1, 5), v = (−3, 4). Новые приведённые стоимости: (3 0), (0 0). Клетка (A2, B2) стала нулевой, клетка (A1, B1) перестала быть нулевой – но перевозок по ней нет.

Поток: A2 везёт оставшиеся 2 единицы в B2. Готово: стоимость 5·5 + 3·2 + 2·9 = 49, оценка D = 5·1 + 5·5 + 3·(−3) + 7·4 = 49.

## 3. Шаг «поток»

Задача шага: имея текущий план, развезти ещё как можно больше груза, пользуясь только нулевыми клетками. Простого «вези, куда можно» недостаточно: иногда нужно *переставить* уже назначенные перевозки. В примере из задания A2 упирается в заполненный B2, и нужно «подвинуть» A1 из B2 в B3, чтобы A2 занял освободившееся место.

Такие перестановки описываются **сетью**. Вершины – поставщики и потребители. Груз может перейти:

- из строки i в столбец j, если клетка (i, j) нулевая (поставщик везёт туда новый груз);
- из столбца j в строку r, если r уже везёт что-то в j (эту перевозку можно уменьшить – не больше чем на её объём, – а высвободившийся груз строка r отправит в другое место).

Путь в этой сети от поставщика с остатком груза до потребителя с дефицитом – это цепочка перестановок, после которой развезено больше груза (в методе потенциалов аналог – цикл пересчёта). Задача «развезти максимум» – это задача о максимальном потоке. Мы решаем её **алгоритмом Диница**, он состоит из раундов:

1. **Поиск в ширину** (`_label_distances`). От потребителей с дефицитом идём по сети «назад» и для каждой вершины находим расстояние – число переходов до ближайшего потребителя с дефицитом. Вершины, от которых до дефицита не добраться, остаются без метки.
2. **Поиск в глубину** (`_blocking_flow`). Каждый поставщик с остатком груза отправляет его по сети, переходя только в вершину, которая на единицу ближе к цели. Поэтому поиск не может зациклиться и идёт только по кратчайшим цепочкам. Каждая вершина помнит, какие свои дуги она уже исчерпала (указатели `next_zero`, `next_feeder`), и не просматривает их повторно.

Раунды повторяются, пока поиск в ширину находит хотя бы одного поставщика с остатком, от которого достижим дефицит. Когда не находит – по нулевым клеткам больше ничего провезти нельзя (поток максимален).

Поиск в глубину записан двумя взаимно-рекурсивными функциями – их удобно читать как описание того, что происходит с грузом:

- `ship_from_row(i, limit)` – «строка i, отправь до limit единиц»: перебирает нулевые клетки строки; если столбец – потребитель с дефицитом, груз остаётся у него; иначе просит столбец освободить место;
- `release_from_col(j, limit)` – «столбец j, освободи место под limit единиц»: уменьшает перевозки других строк в этот столбец, поручая им отправить высвободившийся груз дальше (`ship_from_row`).

Почему поиск в ширину ведётся от потребителей, а не от поставщиков: тогда метку получают только вершины, от которых цель действительно достижима, и поиск в глубину не тратит время на тупики. Первая версия программы вела поиск от поставщиков – раундов было 217, стало 129, а время шага «поток» уменьшилось почти втрое.

## 4. Шаг «потенциалы»

Поток максимален, но груз остался. Пусть **S** – множество вершин без метки, то есть тех, от которых по сети *не* добраться до потребителя с дефицитом. В S входят все поставщики с остатком груза; ни один потребитель с дефицитом в S не входит.

Найдём

```
delta = минимум r[i][j] по клеткам, где строка i ∈ S, а столбец j ∉ S.
```

delta > 0: если бы такая клетка была нулевой, из строки i можно было бы перейти в столбец j, а от него добраться до дефицита – тогда i не лежала бы в S.

Сдвиг: **u[i] += delta для строк из S, v[j] −= delta для столбцов из S.** Посмотрим на четыре типа клеток:

| строка | столбец | что происходит с r |
|---|---|---|
| в S | в S | u выросло, v упало на столько же – r не меняется |
| не в S | не в S | ничего не менялось – r не меняется |
| в S | не в S | r уменьшается на delta; по выбору delta остаётся ≥ 0, а самые дешёвые клетки становятся нулевыми |
| не в S | в S | r увеличивается на delta |

Проверим инвариант. Во всех клетках r ≥ 0 – да. Перевозки остались на нулевых клетках? Нарушить это могла бы только последняя строка таблицы (клетка перестаёт быть нулевой). Но перевозок по таким клеткам нет: если бы строка r ∉ S везла груз в столбец j ∈ S, то из j можно было бы перейти в r, а от r добраться до дефицита – и j не лежал бы в S.

**Почему алгоритм заканчивается.** При каждом сдвиге нижняя оценка D увеличивается ровно на delta·(остаток неразвезённого груза): запасы строк из S превышают потребности столбцов из S как раз на этот остаток. D – целое число и не может превысить стоимость оптимального плана, значит, сдвигов конечное число. После каждого сдвига появляются новые нулевые клетки, ведущие из S наружу, и шаг «поток» продолжает работу.

В конкурсном тесте потенциалы сдвигаются всего 19 раз: цены – целые числа от 1 до 999, а итоговые потенциалы лежат в узком диапазоне (u от 1 до 21, v от −19 до 0).

## 5. Что делает программу быстрой

### 5.1. Список клеток-кандидатов

В таблице 1000×1000 миллион клеток, но в оптимальном плане конкурсного теста занято всего 2038, причём цена каждой не больше 13 (при ценах до 999), а средняя цена перевозки единицы груза – 2,79. Дорогие клетки в решении не участвуют, и просматривать их на каждом шаге незачем.

Поэтому после вычисления начальных потенциалов программа один раз отбирает **клетки-кандидаты** – клетки с начальной приведённой стоимостью не больше порога `threshold` (порог подбирается так, чтобы кандидатов было около 32 на строку; в конкурсном тесте это 30 889 клеток, 3 % таблицы). Шаг «потенциалы» ищет delta и новые нулевые клетки только среди кандидатов.

Важно, что это **не эвристика**, а точный приём. Обозначим r₀ начальную приведённую стоимость. Потенциалы строк только растут, потенциалы столбцов только убывают, поэтому в любой момент

```
r[i][j] = r₀[i][j] − (рост u[i]) + (падение v[j]) ≥ r₀[i][j] − (рост u[i]).
```

У клетки не из списка r₀ > threshold. Значит, пока рост потенциала каждой строки не больше threshold, такая клетка имеет r > 0: она не нулевая и не может оказаться клеткой с минимальным r. Перед каждым сдвигом программа проверяет условие «рост u + delta ≤ threshold» (`_dual_step`). Если оно нарушается, порог удваивается и список пересобирается (`_extend_candidates`), после чего delta ищется заново. Так что ответ всегда тот же, что при работе со всей таблицей. В конкурсном тесте расширять список не приходится (рост потенциалов – 19, порог – 29); в тестах есть проверка, что расширение работает, когда порога заведомо не хватает.

### 5.2. Разделение труда между NumPy и Python

- NumPy (скомпилированный код) делает всё, что касается больших массивов: разбор файла, минимумы строк и столбцов, отбор кандидатов, поиск delta, обновление приведённых стоимостей кандидатов, поиск новых нулевых клеток. Это несколько операций над массивом из 30 тысяч элементов на каждый сдвиг потенциалов.
- Обычный Python обходит сеть нулевых клеток (списки смежности `zero_cols`, `zero_rows`). Сеть маленькая: около 2000 вершин и 2000–2300 дуг.

Сеть нулевых клеток не пересобирается после каждого сдвига: из неё удаляются клетки, переставшие быть нулевыми, и добавляются новые.

### 5.3. Ввод и вывод

- `in.txt` (около 4 МБ текста) читается целиком и разбирается одним вызовом `numpy.fromstring` – примерно 20 мс. Разбор средствами Python (`split` + `int`) занимает около 100 мс.
- В `out.txt` миллион чисел, почти все – нули. Каждая строка собирается из готовых кусков строки `"0 0 0 ..."`, между которыми вставляются ненулевые перевозки (`write_plan`), – около 4 мс на весь файл.
- Стоимость плана считается в целых числах Python, которые не переполняются.

### 5.4. Куда уходит время (конкурсный тест, ~0,18 с)

| Этап | Время |
|---|---|
| запуск интерпретатора Python | ~0,02 с |
| загрузка NumPy | ~0,08 с |
| чтение и разбор `in.txt` | ~0,02 с |
| решение (19 сдвигов потенциалов, 129 поисков в ширину) | ~0,06 с |
| запись `out.txt` | < 0,01 с |

Больше половины времени – запуск Python и загрузка NumPy, на которые программа повлиять не может. Обойтись без NumPy невыгодно: один только разбор миллиона чисел средствами Python занял бы больше, чем загрузка NumPy и разбор вместе.

## 6. Почему выбран этот метод

При разработке были реализованы и измерены три подхода (конкурсный тест, только время решения, без ввода-вывода; все три дали одну и ту же стоимость 1 415 114):

| Метод | Время | Комментарий |
|---|---|---|
| Метод потенциалов: начальный план (минимальный элемент) + улучшение по циклам, базис хранится деревом, вводимая клетка ищется NumPy | 1,2–1,9 с | 10–16 тысяч итераций, каждая – обход цикла и пересчёт потенциалов поддерева на Python |
| Венгерский метод с поиском кратчайшего пути отдельно для каждого поставщика (строки обрабатывает NumPy) | 2,3 с | около 4 тысяч поисков пути, каждый просматривает в среднем 130 строк |
| **Прямо-двойственный метод: поток по нулевым клеткам + сдвиг потенциалов, список кандидатов** | **0,06–0,08 с** | 19 сдвигов потенциалов, вся «массовая» работа – в NumPy |

Причина разницы: Python медленно выполняет циклы, а первые два метода состоят из тысяч мелких шагов, каждый из которых – цикл на Python. Третий метод делает мало крупных шагов; крупный шаг хорошо перекладывается на NumPy.

Начальные планы методов северо-западного угла, минимального элемента и Фогеля мы не используем: им нужен последующий метод потенциалов, который и оказался медленным. Для справки: план по методу минимального элемента на конкурсном тесте стоит 3,6 млн – в 2,5 раза дороже оптимального.

## 7. Границы применимости

- **Числа.** Цены должны помещаться в 64-битные целые (с запасом: до 10¹⁸ по модулю). Запасы, потребности и итоговая стоимость – целые числа Python без ограничения размера. Цены могут быть отрицательными.
- **Нули.** Нулевые запасы и потребности допустимы.
- **Открытая задача.** Если запасов больше, чем потребностей, добавляется фиктивный потребитель с нулевыми ценами; лишний груз остаётся у поставщиков. Если запасов меньше – программа сообщает об ошибке: допустимого плана нет.
- **Размеры.** Таблица может быть прямоугольной (проверено, в частности, 200×3000 и 3000×200).
- **Диапазон цен.** Число сдвигов потенциалов зависит от того, насколько разнообразны цены. При ценах 1…999 это ~20 сдвигов; если цены – произвольные числа до 10⁹, сдвигов становится около 2000 (не больше нескольких тысяч: каждый сдвиг открывает хотя бы один новый путь), и задача 1000×1000 решается за ~2 с. Ответ при этом остаётся точным.
- **Много одинаковых цен.** Если нулевых клеток очень много (например, все цены равны), сеть нулевых клеток становится большой; задача 1000×1000 с одинаковыми ценами решается за ~0,3 с.

## 8. Как мы убеждаемся, что ответ верен

1. **Доказательство в коде** (`verify_plan`, запуск `python main.py --verify`): проверяется допустимость плана и условия оптимальности из раздела 1 по всем клеткам таблицы.
2. **Независимая проверка** (`tools/check.py`): читает только `in.txt` и `out.txt`, потенциалы подбирает сама, другим алгоритмом (Беллмана – Форда). Если потенциалов не существует, план не оптимален – программа это сообщит.
3. **Тесты** (`tests/`): сверка с простым эталонным решателем на сотнях случайных маленьких задач, крайние случаи, форматы файлов.
4. **Три разных метода** из раздела 6 дали на конкурсном тесте одну и ту же стоимость.

## 9. Вопросы и ответы

**Откуда уверенность, что найденная стоимость минимальна?**
Из утверждений раздела 1: потенциалы дают нижнюю оценку стоимости любого плана, а стоимость нашего плана с ней совпадает. Это проверяется программно для каждого ответа.

**Чем метод отличается от метода потенциалов?**
Условие оптимальности то же. Метод потенциалов идёт от допустимого плана к правильным потенциалам, наш – от правильных потенциалов к допустимому плану. Наш путь состоит из малого числа крупных шагов, поэтому он быстрее на Python.

**Может ли алгоритм зациклиться?**
Нет. Поиск в глубину ходит только в вершины с меньшим расстоянием. Каждый раунд шага «поток» развозит хотя бы единицу груза. Каждый сдвиг потенциалов увеличивает нижнюю оценку D хотя бы на 1, а она ограничена сверху. Вырожденность, из-за которой в методе потенциалов возможны «холостые» итерации, здесь не возникает: базисный план нам не нужен.

**Почему в ответе может быть больше N+M−1 ненулевых перевозок?**
Задание требует только допустимый план минимальной стоимости. Оптимальных планов может быть много (когда есть несколько нулевых клеток на выбор), и не все они базисные. В конкурсном тесте занято 2038 клеток при N+M−1 = 1999.

**Почему перевозки получаются целыми?**
Запасы и потребности целые, а алгоритм только складывает, вычитает и берёт минимум – дробям взяться неоткуда.

**Что будет, если список кандидатов выбран неудачно?**
Ничего страшного: условие из раздела 5.1 проверяется перед каждым сдвигом, и список расширяется автоматически. От выбора порога зависит только скорость, но не ответ.

**Какова сложность алгоритма?**
Подготовка – O(N·M): нужно хотя бы прочитать таблицу. Дальше работа идёт с K кандидатами (K ≈ 32·max(N, M)) и сетью из E нулевых клеток (E ≈ N+M): сдвиг потенциалов стоит O(K) операций NumPy, раунд шага «поток» – O(E). Число сдвигов и раундов зависит от данных; в конкурсном тесте – 19 сдвигов и 129 раундов.

**Используются ли готовые решатели?**
Нет. Из NumPy используются только операции над массивами: разбор чисел, минимум, сравнение, выборка по условию, сортировка индексов.
